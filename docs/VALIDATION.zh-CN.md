# 验证报告

[English](VALIDATION.md) · **简体中文**

本文件记录 RepBase 转 RepeatMasker 适配器的验证方式、所用命令、结果，以及已验证与未验证内容的边界。

**本验证的性质：功能兼容性验证。** 它证明转换器能生成格式规范、标识唯一、完整的 RepeatMasker 库，并且 RepeatMasker 能正确读取该库。它**不是**全基因组准确率基准，也**不**证明本库对任何特定基因组优于精选的 2018 RepeatMasker Edition。

## 2. 转换摘要

命令：

```bash
python repbase_to_rm.py \
    --input-dir /path/to/RepBase31.09.embl \
    --mapping   mappings/repbase-to-repeatmasker.toml \
    --output    repbase_31.09.rm.fa \
    --out-dir   reports
```

### 2.1 记录对账

| 项目 | 数量 |
| --- | --- |
| 输入 EMBL 记录 | 126,885 |
| 唯一原始 ID | 124,866 |
| 重复的原始 ID（出现 >1 次） | 1,556（3,575 条记录） |
| — 其中完全一致（同 ID 下所有记录序列相同） | 1,513（3,441 条）→ 丢弃 1,928 |
| — 其中混合（同 ID、序列不同） | 43（134 条）→ 保留 107 条不同序列，丢弃 27 条内部完全重复 |
| 新增的重命名记录（`_dup2` … `_dup13`） | 64 |
| 输出 FASTA 记录 | **124,930** |

对账恒等式：

```
126,885 − 1,955（丢弃的完全重复） = 124,930
124,866（唯一 ID） + 64（重命名）  = 124,930
```

`_dup2` … `_dup13`：拥有最多不同序列的标识符是 `Contig_26`（13 条序列）。

| --- | --- |
| LTR | 75,260 |
| DNA | 27,739 |
| LINE | 13,511 |
| SINE | 2,915 |
| RC | 2,198 |
| PLE | 1,534 |
| Unknown | 863 |

### 2.3 分类覆盖率

| 指标 | 值 |
| --- | --- |
| 已分类记录 | 124,067 |
| 未分类记录 | 863 |
| 覆盖率（记录级） | **99.31%** |
| 未分类的不同原始条目 | 838 |

863 条未分类**记录**对应 838 个未分类的不同**条目**：其中 25 个条目拥有多于一条不同序列，因而被表示为同样携带 `Unknown` 类别的 `_dupN` 重命名记录。两个数字都列出以保持透明；与 124,930 条输出记录口径一致的是记录级数字（99.31%）。

### 2.4 `Unknown` 记录的构成

在 838 个不同的未分类条目中：

- **通用描述符，家族无法确定** ≈ 445 个条目
  （`Transposable Element` 230、`Repetitive element` 72、`Nonautonomous` 52、
  `Repetitive sequence` 50、`Multicopy gene` 26，以及 `conserved` / `Repeat region`
  等）—— 如实标记为 `Unknown`，绝不强行猜测。
- **空 `KW` 字段** —— 93 个条目（完全没有分类信息）。
- **可恢复但未映射** ≈ 300 个条目（`SINE element` 20；`Transfer RNA` / `Small nuclear RNA` 等结构 RNA 变体；`Loki-*-LTR` / `CoeEFV-LTR` 等 LTR 家族；`FLA` / `MITE`）。通过一份有记录的同义词补充表可以恢复这些条目（覆盖率可升至约 99.6%），但按既定范围，它们被保留为 `Unknown`，而非静默映射。

完整列表见 `unmapped_records.tsv`（838 个不同 ID）。

### 2.5 碱基规范化（有记录，非一刀切替换）

| 转换 | 字符数 | 记录数 | 说明 |
| --- | --- | --- | --- |
| `x/X` → `N` | 37,502 | 221 | RepBase 的掩蔽/未知位置 |
| `u/U` → `T` | 8 | 4 | DNA 共识序列中的尿嘧啶残基 |
| `o/O` → `N` | 1 | 1 | `Merlin-5N2_OT` 中的单个非法字符 |

其余所有非 ACGT 字符都是合法的 IUPAC 简并码（`N/R/Y/K/M/S/W/B/D/H/V`，约 430,000 个字符），原样保留。每次转换事件都记录在 `base_normalization.tsv` 中。

### 2.6 标识符净化

166 条记录含有在 RepeatMasker FASTA 标识符中非法的字符（`:`、`(`、`)`、`@`），这些字符被替换为 `_`（例如 `A@1` → `A_1`，`tRNA-Leu-TTA(m)` → `tRNA-Leu-TTA_m_`）。净化之后，输出中**不存在重复标识符**。

### 2.7 可复现性检查

将交付的 CLI 在完整 RepBase 31.09 输入上端到端重跑，并与开发期间的参考库比较：

| 检查项 | 结果 |
| --- | --- |
| `repbase_31.09.rm.fa` 的 SHA-256 | 一致（`72f41f7532a744b82902b11e898c309562fa14c25fdb6ee52d333da3a17611ad`） |
| 字节比较（`cmp`） | 字节级一致 |
| 记录数 / 头部集合 / 逐记录序列 | 124,930 = 124,930；一致；0 处差异 |
| `id_mapping.tsv`、`unmapped_records.tsv`、`base_normalization.tsv`、`duplicate_report.tsv` | 各自字节级一致 |

运行开销：完整 126,885 条记录输入耗时 108 秒（约 100% CPU，峰值内存约 900 MB）。这证明发布的 CLI 能精确复现参考输出，即转换算法与分类规则未发生改变。

## 3. 分类验证

### 3.1 与 2018 RepeatMasker Edition 的交叉验证

命令：

```bash
python scripts/cross_validate.py \
    --old-lib /path/to/repbase_2018.lib \
    --new-lib repbase_31.09.rm.fa
```

| 指标 | 结果 |
| --- | --- |
| 共有名称 | 46,105 |
| 顶层类别一致率 | 45,230 / 46,105 = **98.10%** |
| 完整 class/subclass 一致率 | **60.29%** |

> **说明：** 98.10% 是*与 2018 RepeatMasker Edition 在共有名称上的一致率*，不是分类“准确率”。这里没有独立的标准答案；两个库的差异部分源于它们有意做出的不同建模选择，而不只是“一方对、一方错”。

差异分为四类：

1. **亚类粒度（占分歧的大多数）。** Terrier 止步于超家族层级，因此 `DNA/TcMar-Tc1` → `DNA/TcMar`、`LTR/ERV1` → `LTR/ERV`、`DNA/hAT-Ac` → `DNA/hAT`。这是有意的粗化，不是错误。
2. **真实的现代重分类。** `LINE/Penelope` → `PLE`（307 条记录）。RepeatMasker 4.x 已将 Penelope 视为独立类别，因此本库在此处比 2018 版**更符合当前定义**。
3. **`new = Unknown`**（222 条记录，0.48%）—— 主要是 Terrier 映射中缺失的结构 RNA（`4.5SRNA`、`5S`、`7SK`、`5SrRNA`）。
4. **`tRNA` → `Structural_RNA`**（72 条记录）—— 2018 版把 `tRNA` 用作类别名；Terrier 将其归入 `Structural_RNA`。两者都说得通。

### 3.2 映射行为（单元测试覆盖）

`tests/test_conversion.py` 中的合成测试固化了分类契约：大小写不敏感匹配、首个匹配优先、`Helitron` → `RC/Helitron`（而非 `DNA`）、`Penelope` → `PLE`，以及保留 `Unknown`。

### 3.3 为什么用 Terrier 映射而不用 `embl2rm.pl`

另一种 Cornell `embl2rm.pl` 路线经评估后弃用：它只硬编码四种类别码，会把 `Helitron` 误分类为 `DNA/Helitron`（应为 `RC/Helitron`），且无法表达 SINE 亚类。对比过程见项目历史。

## 4. 序列完整性

将交付库与官方 RepBase 31.09 FASTA 发行版（`RepBase31.09.fasta.tar.gz`，39 个主文件）对账，方法是比较**去重后的规范化序列的 SHA-256 哈希集合**。这是*集合*比较，不是多重集比较：两侧在去重后记录数本就不同。

比较所用规范化（与转换器一致）：转大写、`x→N`、`u→T`、`o→N`。

| 项目 | 官方 FASTA | 本次转换 |
| --- | --- | --- |
| 记录数 | 126,885 | 124,930 |
| 去重后的规范化序列 | 124,924 | **124,924** |
| 本库有而官方无 | — | **0** |
| 官方有而本库无 | 1,955 条记录（各自匹配一条已存在的不同序列） | — |

**结论：** 经序列规范化后，转换库与官方 FASTA 所含的不同序列集合完全相同（124,924 = 124,924）。相对于原始记录，转换按既定去重规则合并了 1,955 条冗余记录，未丢失任何唯一序列；保留的序列没有任何改动（真实的替换、缺失或插入都会破坏哈希匹配）。1,955 条“仅官方有”的记录正好就是按规则丢弃的“同 ID + 相同序列”重复（与 §2.1 对应）。

124,930 条输出记录对应 124,924 条不同序列：有 6 条记录与另一条不同标识符的记录共享同一序列：

```
ID4_Rn#Unknown    = ID4_#SINE/tRNA
ID_Rn1#Unknown    = ID_Rn2#Unknown
B4#SINE/tRNA      = B4_ROD#Unknown
B1F1#SINE/7SL     = B1F1_mur#Unknown
B4A#SINE/tRNA     = B4A_ROD#Unknown
B1F2#SINE/7SL     = B1F2_mur#Unknown
```

这些是不同标识符、但共识序列恰好相同的记录（通常是同一元件一次以特定 SINE 登记、一次以啮齿类条目登记）。这些标识符**并不冲突**——去重以标识符为范围，输出中不含重复标识符（§2.6）——因此不再进一步去重；全局序列唯一性并非要求。

其他结构性检查：

- `makeblastdb -parse_seqids` 在完整库上成功执行。
- 所有标识符唯一，且只含 RepeatMasker 合法字符。
- 每条序列只含 IUPAC 核苷酸字符。

## 5. RepeatMasker 兼容性

### 5.1 数据库构建

```bash
makeblastdb -in repbase_31.09.rm.fa -dbtype nucl -parse_seqids
```

结果：**通过**（124,930 条序列；无重复 `seq_id` 报错，证明去重生效）。

### 5.2 阳性对照功能测试

```bash
RepeatMasker -e rmblast -lib repbase_31.09.rm.fa -xsmall -gff \
    -dir rm_test_out test_genome.fa
```

| 对照 | 期望 | 实测 |
| --- | --- | --- |
| Gypsy-30_AnMe-I | `LTR/Gypsy` | `LTR/Gypsy` ✓ |
| L1-62_AT | `LINE/L1` | `LINE/L1` ✓ |
| Helitron-N7_AT | `RC/Helitron` | `RC/Helitron` ✓ |
| L1-3_CR（Penelope） | `PLE` | `PLE` + 内部 `(GT)n` Simple_repeat ✓ |

| 随机片段 | 无命中 | 无命中 ✓ |

`.tbl` 报告**掩蔽碱基 92.51%** —— 这是**合成、阳性富集**对照集的预期结果（每条序列都取自库本身）。**它既不是基因组 TE 含量，也不是灵敏度指标。**

> `test_genome.fa` 阳性对照集含 RepBase 衍生序列，因此**不**随本仓库分发。

## 6. 真实基因组评估（NTN 甲虫，chr2 前 10 Mb）

在真实昆虫基因组上做了一次相对比较，以刻画其行为：在相同条件下比较三个库。它回答三个问题：(1) RepBase 31.09 相比 2018 版额外提供了多少注释，包括总覆盖率和新增覆盖（不重叠）碱基；(2) 这些新增覆盖是否落在已分类的 TE 类别中，而非低复杂度或 `Unknown`；(3) 更大库的运行时间与内存开销。

**设置：** NTN 甲虫基因组（409.8 Mb，8 条染色体），chr2 前 10 Mb（0% N）；同一台机器与环境（RepeatMasker 4.2.4 / RMBlast 2.17.1）；参数完全相同 `-xsmall -gff -pa 32`；只有库不同。

| 运行 | 库 | 库大小 | 耗时（10 Mb） |
| --- | --- | --- | --- |
| A | RepBase 2018 RM Edition | 49,067 条 | 108 s |
| B | RepBase 31.09（本次转换） | 124,930 条 | 252 s |
| C | Dfam 4.0 `-species "Insecta"` | 6,831 个家族 | 54 s |

`.tbl` 汇总：

| 类别 | 2018 | 31.09 | Δ | Dfam 4.0 |
| --- | --- | --- | --- | --- |
| **掩蔽碱基合计** | 14.66% | **18.08%** | **+3.42pp** | 15.40% |
| 逆转录元件 | 7.27% | 9.77% | +2.50pp | 5.66% |
| — LTR | 3.11% | 5.04% | +1.93pp | 2.74% |
| — LINE | 4.14% | 4.47% | +0.33pp | 2.90% |
| — Penelope (PLE) | 0.00% | 0.23% | +0.23pp | 0.01% |
| — SINE | 0.01% | 0.03% | +0.02pp | 0.01% |
| DNA 转座子 | 3.32% | 4.17% | +0.85pp | 2.69% |
| 环状复制（Helitron） | 0.28% | 0.36% | +0.08pp | 0.05% |
| 未分类 | 0.01% | 0.01% | 0.00pp | **3.30%** |
| 小 RNA | 2.78% | 2.80% | +0.02pp | 2.72% |
| 简单重复 | 0.88% | 0.86% | −0.02pp | 0.88% |
| 低复杂度 | 0.10% | 0.10% | 0.00pp | 0.10% |

碱基级重叠（31.09 vs 2018）：`仅 2018 = 0.04%`、`仅 31.09 = 3.46%`、三方交集 = 1,071,066 bp。

观察：

1. **31.09 保留了 2018 检测结果的绝大部分。** 只有 0.04% 的窗口被 2018 掩蔽而未被 31.09 掩蔽，因此换库后几乎保留了全部 2018 检测结果、同时新增了新的结果。由于这 0.04% 的 2018 检测结果*未*被找回，31.09 不是 2018 的严格超集。
2. **新增覆盖主要归因于已分类的 TE 类别；未观察到明显的低复杂度富集。** +3.42pp 的增益落在 LTR（+1.93pp）、DNA（+0.85pp）、LINE（+0.33pp）、PLE（+0.23pp）和 RC（+0.08pp），而低复杂度为 0.00pp、简单重复为 −0.02pp。这说明了额外覆盖*被归入*了哪些类别；它本身并不证明这些分类在生物学上正确。
3. **结构 RNA 是被重新标注，而非新检测到的：** `SSU-rRNA_Hsa` 与 `LSU-rRNA_*` 在两个库中命中数完全相同（例如 107 = 107、130 = 130）；改变的只是标签（`rRNA`/`snRNA`/`tRNA` → `Structural_RNA`）。小 RNA 总量基本不变（2.78% → 2.80%）。非 TE 的 RNA 记录被两个库以相同方式带入掩蔽 —— 这不是 31.09 引入的行为。
4. **Dfam 4.0 是互补而非可加的：** 其 15.40% 中有 3.30pp 是 `Unclassified`（有共识序列但无 TE 类别标签）。Dfam 还提供了 RepBase 未覆盖的独特注释区域（361,797 bp 被 Dfam 掩蔽、而 31.09 与 2018 均未掩蔽）；本次比较并未确定这些区域的家族来源。两个来源的结果**不可简单相加**；在整合层需要去重与明确的优先级规则。
5. **运行开销：** 每 10 Mb 耗时 252 秒（为 2018 库的 2.3 倍），外推到 400 Mb 基因组、32 线程约需 2.8 小时。

这是**在单个 10 Mb 窗口上的相对行为比较**：它支持在真实序列上评估功能兼容性与注释行为，但其本身不能确立全基因组注释准确率。

## 7. 已知局限

- 输出是**自定义 `-lib` 库**，不是官方精选的 RepBase RepeatMasker Edition。它未在任何地方登记为 “validated”。
- 分类是**关键词映射**，而非基于序列的预测。`KW` 无可映射超家族的记录保持 `Unknown`。
- **863 条输出记录（0.69%）保持 `Unknown`**；若加入一份有记录的同义词补充表，还可恢复约 300 条，但按范围有意未做。
- 对 Tc1/Mariner、ERV1/ERVK、hAT-Ac 等，**亚类粒度比 2018 版更粗**。只保证到超家族层级。
- 库**未限制到任何分类群**；它包含所有 RepBase 物种的记录。
- 库**包含非 TE 类别**（`Satellite`、`Structural_RNA`、`Unknown`、`Other`）。下游用户（如基因预测）可能希望将这些与 TE 类别分开注释或排除。
- 只转换 39 个主 `.ref` 文件；`appendix/` 记录按设计排除。
- 本报告**未**确立全基因组灵敏度/特异度。
- 运行开销随库大小增长（在测试窗口中约为 2018 版的 2.3 倍）。

## 8. 复现步骤

1. 在适用的 GIRI 许可下获取 RepBase 31.09，解压出 39 个主 `.ref` 文件（不要把 `appendix/` 子目录放进输入目录）。
2. 运行转换器（§2），并将打印的摘要与 §2.1–§2.3 对照。
3. 与官方 RepBase FASTA 发行版核对完整性：对序列做规范化（转大写、`x→N`、`u→T`、`o→N`），比较去重后序列的 SHA-256 哈希集合；两侧应各为 124,924 条不同序列。
4. 可选：用 `scripts/cross_validate.py` 与参考库交叉验证分类（§3.1）。
5. 构建 BLAST 数据库（§5.1），并用你自己的阳性对照运行 RepeatMasker 功能测试（§5.2）。
6. 运行合成数据单元测试：`python tests/test_conversion.py`。

本仓库不分发任何 RepBase 数据，因此第 1、5 步需要用户自行获取授权输入。
